## The rulebook

These are the patterns to recognise. The next step ("The Investigation") walks through them in a real, story-driven lab.

| Antipattern | Why it hurts | Fix |
|---|---|---|
| All Time | Scans every bucket regardless of age | Always set a time range |
| `index=*` | Searches all indexes including `_internal` | Always name your index |
| Leading / middle wildcards | Bypasses the Bloom filter; full lexicon scan | Trailing only (`term*`); use `TERM()` for IPs and other minor-breaker values |
| Transforming before streaming | All events hit the search head before filtering | `eval`, `where`, `fields` before `stats`, `chart`, `timechart` |
| `NOT` / `!=` | Bloom filters find presence; absence is slow | Use positive filters: `(a OR b OR c)` |
| `transaction` (no parameters) | Runs entirely on the search head, not distributed | `stats ... by session_id` unless you genuinely need `maxspan` or `startswith` |
| `join` | Sequential; inner search capped at 50k rows | `stats` + `appendcols` or `append`, or a lookup |
| `\| search` after the first pipe | Filter runs on the search head, after all events arrive | Move filter terms before the first `\|` |
| Real-time searches | Continuous load on search heads and indexers | Short-interval scheduled search + panel auto-refresh |
| Verbose mode | Full events sent to the search head even for stats | Smart or Fast mode for aggregations |
| `savedsearch` | Always re-runs the search from scratch | `loadjob` to reuse a finished job's results |
| Zero-result subsearches | Can produce false positives or trigger expensive side effects | Guard the outer search with `require` |
